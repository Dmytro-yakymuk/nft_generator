# Експерименти

Експериментальне дослідження з розділу 3 кваліфікаційної роботи: методика - підрозділ 3.1, результати - підрозділ 3.2 (пункти 3.2.1-3.2.11). Вихідні дані - у `results/*.csv`, графіки - у `../документи/thesis-images/exp-*.png` (каталог документів поза репозиторієм).

| Експеримент | Пункт роботи | Що вимірюється | Як запустити |
|---|---|---|---|
| E1, E2 | 3.2.3 | час генерації колекції через REST API: від кількості зображень N = 100, 1 000, 5 000, 10 000 (5 шарів по 7 варіантів) і від кількості шарів n = 3, 5, 7, 10 (по 10 варіантів, N = 1000); два способи генерації - послідовна без кешу шарів (мітки `E1`, `E2`) і паралельна з кешем шарів, 12 воркерів (`E1-parallel`, `E2-parallel`) | `make up`, потім `node experiments/generation-time.js` (`E1` або `E2` - лише один; `REPEATS` - кількість повторів, за замовчуванням 5); паралельна генерація - на поточному образі з `LABEL=E1-parallel` / `LABEL=E2-parallel`, послідовна - на образі застосунку `generator-app:pre-parallel` (`docker tag generator-app:pre-parallel generator-app:local && docker compose up -d app`) |
| E3 | 3.2.1 | час одного перетворення номера комбінації: послідовне інкрементування лічильника проти прямого обчислення, C = 10^2...10^10 -> `results/conversion.csv` | `GENERATOR_EXPERIMENTS=$PWD/experiments/results go test -run ExperimentConversion -v -timeout 1h ./collections/layers/` |
| E3 на платформі | 3.2.1 | генерація 20 зображень з 8 / 9 / 10 шарів по 10 варіантів за двох способів перетворення номера: послідовне інкрементування (мітка `E3-old`, образ `generator-app:pre-perf`) і пряме обчислення (`E3-new`) -> `results/generation-live.csv` | `REPEATS=3 LABEL=E3-new OUT=experiments/results/generation-live.csv node experiments/generation-time.js E3`; для послідовного інкрементування - той самий запуск з `LABEL=E3-old` після `docker tag generator-app:pre-perf generator-app:local && docker compose up -d app` |
| E4 | 3.2.2 | вибір N різних номерів з C = 100 000 комбінацій трьома способами: повторні спроби з переініціалізацією генератора перед кожним зображенням, повторні спроби з однією ініціалізацією, алгоритм Флойда -> `results/sampling.csv` (стовпець `draws` для Флойда - 2N - 1: N чисел на вибір і N - 1 на перемішування `rand.Shuffle`) | `GENERATOR_EXPERIMENTS=$PWD/experiments/results go test -run ExperimentSampling -v -timeout 1h ./collections/layers/` |
| E5 | 3.2.4 | газ whitelist: корінь Меркла (`CollectionNFT`) проти `mapping` (`gas/CollectionNFTMapping.sol`) для N = 10, 100, 1 000, 10 000 адрес -> `results/gas.csv` | `make contracts` (якщо немає `contracts/bin`), потім `node experiments/gas.js` - піднімає тимчасовий Anvil на порті 8546 |
| E6 | 3.2.5 | публікація колекції в IPFS: час, однаковість CID при повторній публікації, доступність файлів через шлюз -> `results/ipfs.csv` | `make up` (з вузлом IPFS), потім `node experiments/ipfs-publish.js` (`AMOUNTS`, `REPEATS`, `GATEWAY`) |
| E7 | 3.2.10 | завантаження головної сторінки в Chromium з вимкненим кешем, без обмеження мережі й на "повільному 4G": передані й розпаковані байти, FCP, LCP, подія load для трьох збірок клієнта - без оптимізацій (`before`), з мінімізацією й стисненням (`compressed`), з усіма оптимізаціями (`optimized`) -> `results/web.csv` | платформа із запущеною збіркою клієнта, потім `LABEL=<мітка> node experiments/web-vitals.js` (`BASE`, `REPEATS`) |
| E8 | 3.2.6 | відповідність частот варіантів заданим ймовірностям: критерій хі-квадрат для кожного з 26 шарів демонстраційного набору, N = 1 000 і 10 000 -> `results/frequencies.csv`, `results/frequencies-detail.csv` | спершу набір шарів: `~/.nvm/versions/node/v22.*/bin/node scripts/demo-art/render.js` (Playwright з глобального встановлення, результат - `data/demo-art`), потім `GENERATOR_EXPERIMENTS=$PWD/experiments/results go test -run ExperimentFrequencies -v ./collections/layers/` |
| E9 | 3.2.7 | унікальність за нерівномірних ваг: спроби й частка найімовірнішого варіанта залежно від N / C, C = 1 296 -> `results/uniqueness.csv` | `GENERATOR_EXPERIMENTS=$PWD/experiments/results go test -run ExperimentUniqueness -v ./collections/layers/` |
| E10 | 3.2.8 | генерація демонстраційної колекції (26 шарів з вагами) через REST API: паралельна з кешем шарів для N = 100, 1 000, 10 000 (мітка `ART-parallel`) і послідовна без кешу для N = 100 і 1 000 (`ART`); частоти атрибутів у метаданих 1 000 токенів -> `results/frequencies-platform.csv` | `make up`, набір у `data/demo-art`, потім `LABEL=ART-parallel AMOUNTS=100,1000,10000 node experiments/generation-time.js ART` (за замовчуванням N = 100 і 1 000); послідовна генерація (N = 100 і 1 000) - без `LABEL` на образі `generator-app:pre-parallel`, як в E1 |
| E11 | 3.2.9 | генерація 500 зображень демонстраційного набору функцією сервера з 1, 2, 4, 6, 8, 10 і 12 воркерами -> `results/parallel.csv` | набір у `data/demo-art`, потім `GENERATOR_EXPERIMENTS=$PWD/experiments/results go test -run ExperimentParallel -v -timeout 1h ./collections/layers/` |
| E12 | 3.2.11 | порівняння з HashLips Art Engine: час генерації й обсяг файлів тих самих наборів (E1 і набір з 26 шарів) для N = 100, 1 000, 10 000 -> `results/hashlips.csv`; платформа - з одним воркером (мітки `E1-1worker`, `ART-1worker`) і з 12 воркерами | `node experiments/hashlips/run.js [E1\|ART]` (Node 18; HashLips ставиться в `data/hashlips`), платформа з одним воркером - див. `hashlips/README.md` |
| E12, стиснення PNG | 3.2.11 | ті самі набори на платформі з 12 воркерами й найшвидшим стисненням PNG (`best-speed`): час і обсяг проти стиснення за замовчуванням (мітки `E1-parallel`, `ART-parallel`) | `GENERATION_PNG_COMPRESSION=best-speed docker compose up -d --wait app`, потім `LABEL=E1-bestspeed AMOUNTS=100,1000,10000 node experiments/generation-time.js E1` і `LABEL=ART-bestspeed AMOUNTS=100,1000,10000 ... ART` (зберегти й повернути `results/frequencies-platform.csv`); назад - `docker compose up -d --wait app` |
| E12, розкладання часу | 3.2.11 | час одного зображення за етапами - завантаження й декодування шарів, накладання, кодування PNG (і з найшвидшим стисненням) - у HashLips (node-canvas) і на платформі (Go) на 300 зображеннях, два прогони на продуктивному ядрі -> `results/breakdown.csv` (вивід скриптів - `results/breakdown.txt`) | `docker run --rm --cpuset-cpus=2 ... golang:1.17-alpine go run experiments/hashlips/breakdown.go 300 <каталоги шарів>` і `taskset -c 2 node experiments/hashlips/breakdown.js 300 <каталоги шарів>` (Node 18); каталоги - робочі каталоги `run.js` у порядку шарів з їхнього `src/config.js`, повні команди - у заголовках скриптів. Міряти в режимі живлення performance: у balanced час на ~15 % більший |
| E12, межа HashLips | 3.2.11 | генерація N = 13 000 зображень набору E1 у HashLips (сумарний ліміт `uniqueDnaTorrance` = 10 000) -> `results/hashlips-limit.txt` | `AMOUNTS=13000 REPEATS=1 OUT=<тимчасовий файл> node experiments/hashlips/run.js E1` |

Графіки й зведені таблиці: `python3 experiments/plot.py` (потрібен matplotlib).

Умови вимірювань і повтори описано в підрозділі 3.1 роботи: кожне вимірювання часу - 5 повторів (перевірка E3 на платформі й генерація 10 000 зображень в E12 - 3), у таблицях - середнє, відносне стандартне відхилення - у тексті; газ - одне вимірювання, бо він детермінований.
